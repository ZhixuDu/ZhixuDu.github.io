Greedy Expert Duplication Algorithm for MoE GPU Load Balancing

What is a simple algorithm to replicate hot experts across GPUs to equalize token load?

Answer

A simple approach is iterative: copy the most-used expert from the most-loaded GPU to the least-loaded GPU, move half of the load gap over, and repeat until all GPUs process nearly the same number of tokens. MoE-GPS: Guidelines for Prediction Strategy for Dynamic Expert Duplication in MoE Load Balancing (Ma et al., 2025) gives this procedure as Algorithm 1 for dynamic expert duplication in MoE inference.

The inputs are a token-to-expert map f, the memory capacity of each GPU, an initial expert placement P (which experts live on which GPUs), and a maximum number of copies per expert. First, each token is assigned to the lowest-indexed GPU that hosts its expert, and the load L of each GPU is counted. While the most-loaded GPU exceeds the least-loaded GPU by more than one token, the algorithm sets the transfer amount to the ceiling of half the load difference, then picks the expert on the most-loaded GPU that serves the most tokens there. If that expert is not already on the least-loaded GPU, has fewer copies than the limit, and fits in that GPU's memory, its weights are copied and the placement is updated. The first transfer-amount tokens of that expert are then reassigned to the least-loaded GPU and both loads are updated. The output is a balanced placement and a token dispatch.

In the paper's framing, the predicted distribution is used before routing to decide where to duplicate experts, and the authors assume prediction and placement happen every batch. Other systems use intervals ranging from every single batch to every 10 minutes. Copy cost is modest: moving one FP16 Mixtral 8x7B expert takes about 0.1 ms over NVLink 3.0 and can be hidden behind attention computation.

With accurate predictions this procedure balances FFN compute; prediction errors leave residual imbalance, which the paper models separately.

Setup

Mixtral 8x7B (with Llama-MoE and Switch Transformer in the appendix) on MMLU, Alpaca Eval and SST2, batch size 1 and sequence length 512. Latency is simulated for a single Transformer layer of prefill (time to first token) with an extended LLMCompass simulator, on four A100 GPUs fully connected by NVLink 3.0 (2 TB/s) or PCIe 4.0 (32GB/s), using tensor parallelism for attention and expert parallelism for FFN layers. Predictor overhead is measured on A100 GPUs. Compared: no prediction, Distribution-Only Prediction, and Token-to-Expert Prediction at a range of accuracies.

The algorithm is specified in pseudocode and used inside the paper's simulator; no separate runtime of the placement algorithm itself is reported.
