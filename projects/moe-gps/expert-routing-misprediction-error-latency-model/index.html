Modeling Expert Routing Misprediction Cost in Multi-GPU MoE

How do expert routing misprediction errors translate into load imbalance latency on multi-GPU systems?

Answer

Prediction errors translate into residual load imbalance on the GPU that ends up with the most tokens. With error rate ε, the typical case assumes errors spread evenly across GPUs, so the most-loaded GPU processes up to (1+ε) times the average token count. In the pessimistic case all errors land on one GPU, which then handles up to N(1+ε) times the average for N GPUs. In the optimistic case the errors do not hurt balance at all. MoE-GPS: Guidelines for Prediction Strategy for Dynamic Expert Duplication in MoE Load Balancing (Ma et al., 2025) uses this three-case model, with the typical case as the default in its simulations.

The error rate ε is defined per strategy. For Token-to-Expert Prediction, which predicts each token's expert, ε is 1 minus accuracy. For Distribution-Only Prediction, which predicts only each expert's share of tokens, ε is the averaged L1 distance over the number of experts. Using ε = 0.1 as an example, the optimistic case corresponds to predicting 85% of tokens for an expert that actually receives 75%, where duplication still yields perfect balance. The pessimistic case is unlikely but bounds performance degradation.

Communication is treated differently from compute. Under expert parallelism with Token-to-Expert Prediction, tokens are sent directly to the GPU of their predicted expert, and any misrouted token must trigger an extra inter-GPU transfer. Communication cost therefore always increases with prediction error, and no optimistic case exists for it. The typical-case assumption is applied to communication as well.

In the simulations, this error rate scales the runtime of the GPU that processes the most tokens. For example, the measured distribution estimation error rates for Mixtral 8x7B are 1.80% on MMLU, 0.98% on Alpaca Eval and 16.00% on SST2, and lower error led to better simulated performance.

Setup

Mixtral 8x7B (with Llama-MoE and Switch Transformer in the appendix) on MMLU, Alpaca Eval and SST2, batch size 1 and sequence length 512. Latency is simulated for a single Transformer layer of prefill (time to first token) with an extended LLMCompass simulator, on four A100 GPUs fully connected by NVLink 3.0 (2 TB/s) or PCIe 4.0 (32GB/s), using tensor parallelism for attention and expert parallelism for FFN layers. Predictor overhead is measured on A100 GPUs. Compared: no prediction, Distribution-Only Prediction, and Token-to-Expert Prediction at a range of accuracies.

An analytical error model applied to FFN compute and expert-parallel communication in simulation of Mixtral 8x7B prefill; the typical case is the default.
