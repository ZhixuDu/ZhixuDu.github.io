Tamper-Evident Audit Logs for LLM Multi-Agent Systems

What should a tamper-evident audit log for LLM multi-agent systems contain?

Answer

AUDITA (Du and Chen, 2026) specifies a message format for this purpose (Definition 1). Each inter-agent message contains its author, its payload, a citation set of hashes of the messages it acts on, an effect predicate stating the world- or work-state change the author commits to, and an Ed25519 signature over those fields, together with pinned seed and model identifiers for replay. Messages are sealed into append-only epochs: when an epoch closes, the recorder signs the Merkle root of its messages and chains it to the previous block's hash.

Each field has a job. A citation is an admission by the author that a message was issued because of another, so the causal graph is authored rather than inferred. The effect predicate lets an auditor check whether a command's effect actually arrived. The seeds make counterfactual replay possible. The paper notes that standard agent-observability logs lack exactly these three fields. On the bus, uncited commands are rejected and every delivery is acknowledged, so dropped messages are detectable. Verification splits the record into certified, suspect and missing sets, and attribution runs only on the certified set.

Two guarantees follow. Under Proposition 3, forgeries never enter the certified graph and leave the verdict unchanged, while deletions can only widen a fully certified agent's responsibility interval and never raise its lower end. Under Theorem 3, erasing evidence produces flagged uncertainty attributed to the item's author, never a clean acquittal.

The paper replayed the same forgeries against the certified record and against an unsigned copy holding the same text. The unsigned copy was driven to 0.365 error and framed an innocent agent in all 450 probes, while the certified verdict stayed at 0.000. Across 450 deletion cells the widened interval always contained the true responsibility, with error at most 0.122. Overhead was 393 B per signed message and 118 KB per incident.

Setup

Reference implementation in Python with Ed25519 signing, Merkle epoch commitments in the style of transparency logs, enforced citation and delivery receipts, and a three-tier store (hot append-only log, content-addressed payloads, cold sealed epochs). Record attacks (forgery and deletion at rising corruption rates) were replayed on CulpaBench incidents against the certified record and against an unsigned copy that keeps message text but drops signatures and seals.

Guarantees assume unforgeable signatures, collision-resistant hashing, attacks against already sealed epochs, and keys that are never stolen; evidence is from simulated incidents.
