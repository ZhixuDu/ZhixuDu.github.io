GPU Memory Wasted by Inactive Experts in MoE Inference

How much GPU memory do inactive experts waste in MoE inference?

Answer

A lot, in large MoE models. In SiDA-MoE (Du et al., MLSys 2024), feeding SST2 sentences to Switch Transformers showed that effective GPU memory utilization, the share of resident memory holding parameters actually used in the forward pass, can fall to about 5% for large models. For short sentences the ineffective memory is around 24GB for Switch-base-128 and 50GB for Switch-base-256. Even for the longest SST2 sentences of 80 tokens it is still around 20GB and 46GB.

The waste follows from where the parameters are. Table 2 of the paper gives the split: Switch-base-8 is 2.298 GB with 1.7932 GB in MoE layers (78.03%); Switch-base-64 is 14.112 GB with 13.608 GB in MoE layers (96.42%); Switch-base-128 is 27.614 GB with 27.11 GB (98.17%); Switch-base-256 is 54.62 GB with 54.114 GB (99.07%). Since each token uses one expert per layer, and a whole sentence typically uses only a fraction of the experts, most of this memory is idle during any single forward pass. The paper compares these sizes with mainstream GPUs that peak at 48GB, many at 24GB, and mobile GPUs at 4GB to 12GB.

SiDA-MoE targets this idle memory by predicting which experts an input will use and keeping only those on the GPU, holding the rest in host main memory. It reports over 80% GPU memory reduction on short SST2 sentences, savings of 6.28GB and 19.84GB on MRPC for Switch-base-128 and Switch-base-256, and 4.52GB and 9.92GB on MultiRC inputs of 200 to 500 tokens.

Setup

Switch-base-8/64/128/256 parameter sizes from Table 2; effective memory utilization measured by feeding SST2 sentences (up to 80 tokens) at batch size 1 and counting parameters used in the forward pass.

Memory utilization was measured on SST2 for Switch Transformer base models with top-1 routing; longer inputs use more experts and thus more of the memory.
