How Much MoE Inference Time Goes to Routing and Dispatch

What fraction of MoE inference latency is spent on routing and expert dispatch?

Answer

A large share, and it grows with the number of experts. Profiling in SiDA-MoE (Du et al., MLSys 2024) on SST2 at batch size 1 found that MoE overhead, defined as expert selection, expert invocation and additional communication, consumes over 72% of total inference time for Switch-base-256. The overhead share was 0.05% for Switch-base-8, 41.47% for Switch-base-64, 56.15% for Switch-base-128 and 72.3% for Switch-base-256.

The reason small batches are slow is explained in the paper's Remark 1: with a small batch, each expert receives very little input, so the cost of invoking an expert exceeds the computation it performs. The number of experts called therefore dictates overall inference time. The default implementation also invokes every expert regardless of whether any token is assigned to it, to suit high-throughput hardware use with many requests. For the comparison the authors built a proxy for ideal inference that replaces the router with a lookup table and invokes an expert only if a token is assigned to it.

These measurements motivate moving expert selection off the critical path. SiDA-MoE predicts each token's expert ahead of time in a parallel thread and only keeps and invokes the predicted experts. With this, latency on Switch-base-128 and Switch-base-256 drops to 25% of the baselines on SST2 and MRPC and to 60% on MultiRC, and the abstract reports up to 72% latency reduction. The gains are smallest for Switch-base-8, where overhead was already negligible: throughput gains there are 1.01x to 1.04x.

The paper also notes that expert selection overhead scales up as model size increases, so the problem grows as more experts are added per layer.

Setup

Profiling of Switch-base-8/64/128/256 on SST2 at batch size 1 on an A100 80GB GPU. The ideal-inference proxy replaces the router with a lookup table and invokes only experts that receive tokens.

The overhead breakdown was measured at batch size 1 on SST2 with the Hugging Face Switch Transformer implementation, which invokes all experts by default.
