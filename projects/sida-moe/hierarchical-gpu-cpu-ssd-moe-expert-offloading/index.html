Offloading MoE Experts to SSD for Trillion-Scale Models

Offloading MoE experts to SSD for models larger than CPU memory

Answer

SiDA-MoE (Du et al., MLSys 2024) offloads inactive experts from GPU memory to host main memory, and its discussion section identifies main memory capacity as the limit of that design. For a model such as Switch-c-2048, with almost 5TB of parameters, main memory may not suffice. The authors propose a layered offloading mechanism that moves experts between GPU memory, main memory and SSD storage as a direction for handling larger models. This SSD tier is proposed, not implemented or evaluated in the paper.

The existing system already provides the pieces such a hierarchy would build on. A hash-building thread predicts, before inference, which expert each token will use at every MoE layer, and the inference thread loads those experts onto the GPU while evicting others first-in-first-out under a memory budget. Look-ahead prediction is what would make a slower tier usable, since transfers can be started before the layer runs. On a single A100 80GB GPU with CPU main memory, this gives up to 80% GPU memory saving on Switch Transformers up to Switch-base-256 (54.62 GB).

The discussion also proposes a different predictor. The current one is an LSTM over the input embeddings. The authors state that expert activation is conditionally dependent on activation patterns in preceding MoE layers, and suggest a graph-structured hash function that stores these cross-layer dependencies for fast lookup. The paper does not report measurements of cross-layer activation dependency.

Setup

The implemented system uses one A100 80GB GPU and host main memory (64 Intel Xeon Platinum 8358 CPUs) with Switch-base-8/64/128/256; SSD offloading and the graph predictor are discussion items without experiments.

The SSD tier and cross-layer graph predictor are proposals in the discussion section; only GPU and CPU main memory offloading was evaluated.
