Running MoE Models Larger Than GPU Memory via Expert Offloading

How can I run a Mixture-of-Experts model that does not fit in a single GPU's memory?

Answer

You can serve a Mixture-of-Experts (MoE) model that exceeds GPU memory by keeping only the experts a given input will actually use on the GPU and holding all other experts in host main memory. In SiDA-MoE (Du et al., MLSys 2024), a predictor decides before inference which experts each token needs, so those experts are loaded ahead of time instead of after each router call. On Switch Transformers this gives up to 80% GPU memory saving.

The approach works because MoE layers hold most of the parameters while most experts sit idle for any one input. MoE layers hold 78.03% of the parameters of Switch-base-8 and 99.07% of Switch-base-256, whose full size is 54.62 GB. The paper notes that high-end GPUs remain around 80GB and commodity GPUs are limited to 48GB or less, while modern server CPUs support terabytes of main memory. Simply offloading experts and fetching them after each router decision breaks the forward pipeline and adds large CPU-GPU transfer overhead, which is why prediction ahead of time matters.

SiDA-MoE runs two threads. A hash-building thread applies an offline-trained predictor (an LSTM with sparse attention) to the next batch and builds a table of the expert and scaling factor for every token at every MoE layer. An inference thread, working on the previous batch, loads the predicted experts to the GPU and moves inactive ones to RAM, evicting experts first-in-first-out when the memory budget is full. The routers themselves are offloaded and do not run in the forward pass.

Reported results: over 80% GPU memory reduction on short SST2 sentences; savings of 6.28GB and 19.84GB for Switch-base-128 and Switch-base-256 on MRPC; and savings of 4.52GB and 9.92GB on MultiRC inputs of 200 to 500 tokens. Throughput rises up to 3.93x over the baseline average, and across GPU memory budgets from about 10 to 80 GB expert offloading gives higher throughput than layer-wise model parallelism. The cost is approximate routing: task fidelity is 97.49% to 98.95% for Switch-base-8 and 92.56% to 93.02% for Switch-base-128.

Setup

Switch Transformer base models with 8, 64, 128 and 256 experts per MoE layer (Switch-base-8/64/128/256), implemented on the Hugging Face transformers Switch Transformer code. Tasks: SST2 and MRPC from GLUE (short and mid-length sentences), MultiRC from SuperGLUE (long inputs), and C4 for perplexity. Hardware: one A100 80GB GPU with 64 Intel Xeon Platinum 8358 CPUs @ 2.60GHz. Baselines: Standard inference, DeepSpeed inference, and Tutel. Latency and memory are measured at batch size 1.

Shown for Switch Transformer base models (8 to 256 experts per layer) on a single A100 80GB GPU with experts offloaded to CPU main memory, on GLUE/SuperGLUE classification tasks.
