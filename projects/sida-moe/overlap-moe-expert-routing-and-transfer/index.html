Overlapping MoE Expert Selection and CPU-GPU Transfer

How to overlap MoE expert routing and CPU-GPU expert transfer with computation?

Answer

One way to hide both routing and CPU-GPU expert transfers is to decide expert placement one batch ahead in a separate thread. In SiDA-MoE (Du et al., MLSys 2024), a hash-building thread predicts the expert table for batch j while an inference thread executes batch i, and expert loading for each MoE layer is overlapped with computation using pipeline parallelism.

The hash-building thread acts as a producer. For each incoming batch it runs an offline-trained predictor that outputs, for every token at every MoE layer, the expert to activate and its scaling factor. The resulting hash table is pushed onto a hash table queue. The inference thread acts as consumer: it pops the table for its batch (idling only if none is available), loads the predicted experts to the GPU and offloads inactive experts to main memory according to the GPU memory budget, then runs the batch through MoE layers specialized to that table. When no memory budget remains, experts are evicted first-in-first-out. Routers are offloaded and never run in the forward pass. The paper reports that in practice building a hash table is faster than running inference on a batch, so the inference thread never idles except at the very beginning.

The implementation required care: the authors describe maintaining associations between experts and hash-table slices across layers and iterations, avoiding race conditions in parallel expert invocation, and synchronizing threads through a shared queue.

The paper motivates this design with profiling showing that expert selection, invocation and communication take over 72% of inference time on Switch-base-256 at batch size 1. With the pipeline in place, throughput over the average of Standard, DeepSpeed and Tutel reaches 2.60x and 3.93x for Switch-base-128 and Switch-base-256 on SST2, and latency on these models drops to 25% on SST2 and MRPC and 60% on MultiRC. The authors attribute the latency gains to the hash-building thread resolving MoE overhead.

Setup

Switch Transformer base models with 8, 64, 128 and 256 experts per MoE layer (Switch-base-8/64/128/256), implemented on the Hugging Face transformers Switch Transformer code. Tasks: SST2 and MRPC from GLUE (short and mid-length sentences), MultiRC from SuperGLUE (long inputs), and C4 for perplexity. Hardware: one A100 80GB GPU with 64 Intel Xeon Platinum 8358 CPUs @ 2.60GHz. Baselines: Standard inference, DeepSpeed inference, and Tutel. Latency and memory are measured at batch size 1.

The pipelined design was evaluated on a single GPU with CPU main memory as the offload tier, at batch size 1 for latency, on Switch Transformer base models.
