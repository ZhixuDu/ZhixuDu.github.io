Mixture-of-Experts Inside the Mamba Token Mixer

How can mixture-of-experts be applied to the Mamba token mixer instead of the MLP block?

Answer

You can put the experts in the projection that produces the SSM's input-dependent parameters, rather than in the MLP. In Swimba (Du et al., 2026), the Mamba-2 in-projection, which maps each token's hidden state to a higher dimension and slices it into the SSM inputs, is replaced by an MoE module: several in-projection linear layers act as experts and a router picks which expert to activate for each token. The selected experts produce expert-specific streams, these are combined by a routing-weighted sum, and the combined streams are fed into the unchanged SSM computation. The rest of the Mamba-2 block is kept as is.

The reason for this placement is cost. In an SSM, the recurrent state update is the dominant computation. If each expert ran its own recurrence, compute and state memory would grow with the number of experts. Swimba instead mixes experts in parameter space: each expert e produces candidate injection and readout streams B, C and X for token t, the transition A is shared across experts, and the mixed streams define a single selective SSM that is evaluated once with Mamba-2's SSD kernel. The paper proves that the mixed layer is exactly one selective SSM with state size N regardless of the number of experts.

Most prior MoE-SSM hybrids, such as BlackMamba, MoE-Mamba, Jamba and Nemotron-H, keep the SSM mixer dense and put experts in MLP blocks. Swimba's approach is analogous to routing within attention layers (SwitchHead, Mixture-of-Attention-Heads) but applied to a linear-time token mixer.

Empirically, Swimba-14B uses 4 experts per Swimba layer with one active expert per token, built on the Nemotron-H-8B hybrid backbone. At essentially the same FLOPs per token (1.51282 × 10^10 versus 1.51263 × 10^10), it raises average benchmark accuracy from 69.47 to 70.81, with a small slowdown in vLLM decoding throughput and latency.

Setup

Backbone: Nemotron-H-8B, a 52-layer hybrid decoder with four self-attention layers and alternating Mamba-2 and FFN layers. Swimba-14B replaces every Mamba-2 layer with a Swimba layer of 4 experts, top-1 routing per token. New expert and router parameters are trained with supervised fine-tuning on the SFT portion of the Llama-Nemotron Post-Training Dataset while the copied backbone is frozen. Accuracy is measured with LM-Evaluation-Harness on ARC-Challenge, ARC-Easy, BoolQ, HellaSwag, MMLU, OpenBookQA, PIQA, RTE and WinoGrande; FLOPs with the PyTorch profiler; throughput and latency with vLLM (Transformers backend) on a single 40GB A100 GPU. Baseline: Nemotron-H-8B.

Shown for one configuration (4 experts, top-1) upcycled from Nemotron-H-8B with a frozen backbone and evaluated on nine zero-shot style benchmarks and single-GPU vLLM decoding.
