Scale-Invariant Normalization and Federated Model Aggregation

How does the scale-invariant property of normalization layers help federated aggregation?

Answer

Scale invariance keeps the weight norms of different clients balanced, so averaging in federated learning is not dominated by clients whose weights grew large. Rethinking Normalization Methods in Federated Learning (Du et al., 2022) calls this adaptive balancing and argues it makes normalization layers indispensable in FL.

Batch normalization (BN) and layer normalization (LN) are scale-invariant with respect to the weights W of the preceding layer: BN(h; W) = BN(h; aW) for any non-zero scalar a. Two consequences follow. First, the gradient with respect to aW is 1/a times the gradient with respect to W, so large weights receive small gradients and small weights receive large ones, an automatic learning-rate tuning effect. Second, Lemma 1 states that if f(λW) = f(W) for all non-zero λ and the gradient exists, then W transpose times the gradient of f is zero. The proof differentiates both sides with respect to λ and sets λ = 1.

Because the gradient is orthogonal to W, a gradient step adds no cross term to the squared norm: the new squared norm equals the old squared norm plus the squared learning rate times the squared gradient norm (Eq. 5). Applied over all steps, the squared norm at step t+1 equals the squared initial norm plus the squared learning rate times the sum of squared gradient norms (Eq. 7). Since FL clients start from the same initialization, and the auto-tuning effect magnifies or shrinks gradients to push norms toward an equilibrium regardless of the input distribution, client weight norms do not drift far from the initialization or from one another.

This matters because, for a fully connected layer with whitened inputs, feature deviation equals weight norm, and a client with a much larger norm would obliterate the others during averaging. In FedAvg experiments on non-IID CIFAR-10, VGG-11 without normalization reaches 36.51% versus 63.52% with LN. The paper prefers LN over BN because BN's running statistics mismatch across clients.

Setup

FedAvg on CIFAR-10 with a pathological non-IID split following McMahan et al. (2017): 100 devices, each holding 2 random classes with 100 samples per class, and 10 randomly sampled devices per communication round. Local epochs E = 10, batch size 64, SGD with learning rate 0.01, 5000 communication rounds, three random seeds. Architectures: VGG-11, ResNet-18 and a small CNN (two 5x5 conv layers and three fully connected layers). Compared normalization: group, layer, instance and batch normalization, fixed batch normalization (training statistics not aggregated), and no normalization. Hardware: a server with two Intel Xeon E5-2687W CPUs and four Nvidia TITAN RTX GPUs.

The norm-balancing result is a derivation for scale-invariant layers trained with gradient steps from a shared initialization; supporting accuracy results come from FedAvg on label-skewed CIFAR-10.
