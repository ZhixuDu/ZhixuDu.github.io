Token-Level Model Selection Among LLMs as an MDP

How can choosing among several LLMs at each decoding step be formulated as an MDP?

Answer

Treat each language model as a policy and the choice of model as an action taken by a controller at every decoding step. Du et al. (2026) formulate token-level mixture-of-agents this way. The state is the prompt plus the tokens generated so far, the next token is appended deterministically, generation ends at an end-of-sequence token or a length cap, and the terminal reward is a task checker's verdict. A controller selects agent k with probability sigma(k | s) and then samples from that agent, so the effective next-token policy is the mixture of agent policies weighted by sigma (Eq. 3).

The controller's objective is to maximise the expected checker reward subject to an expected compute budget on the summed per-token FLOPs of the selected agents (Eq. 4). The formulation is idealised: each agent's prefix cache is assumed available and switching agents costs nothing. An agent choice matters twice, through its immediate cost and through the continuation, because different agents can emit different tokens and lead to different states.

When the target response is fixed in advance, the problem simplifies. The admissible agents at each position are those whose greedy prediction equals the reference token, and all of them emit the same token and reach the same next state, so the remaining cost is shared. The Bellman recursion becomes J_t = d_F(t) + J_{t+1} with J_{T+1} = 0 (Eq. 7), and the minimum-cost controller picks the cheapest matching agent at each position (Eq. 8). The total equals the sum of per-token sufficient compute (Eq. 9). Algorithm 1 computes this with teacher forcing and marks positions with no matching agent as unresolved.

The simplification does not hold off the reference. The paper's handover experiments show that letting a 0.5B model generate on its own moves accuracy relative to Qwen2.5-72B from -0.09 points at one token to -9.44 points at 64 tokens. Related formulations include COLLAB, which selects off-the-shelf policies in a shared decoding MDP by long-term utility, and CITER, which casts small/large token routing as an MDP.

Setup

Measurement panels of fifteen models: Qwen2.5 (0.5B to 72B, seven sizes), OLMo-2 (1B, 7B, 13B, 32B) and DeepSeek-R1-Distill-Qwen (1.5B, 7B, 14B, 32B), with Falcon3 (1B, 3B, 7B, 10B) for cross-family replication. References are checker-verified responses from Qwen2.5-72B-Instruct (four samples per prompt at temperature 0.7, top-p 0.95, earliest passing sample kept), with Llama-3.3-70B-Instruct as a second generator. Core datasets are GSM8K, MATH-500 and HumanEval (1,800 Qwen-written references: 1,281, 375 and 144), within twelve benchmarks totaling 50,019 prompts. Teacher-forced scoring runs in vLLM 0.14.1 with BF16 on eight 80 GB A100-SXM4 GPUs; uncertainty uses 2,000 item-bootstrap resamples.

The greedy-optimality result assumes a fixed verified reference, greedy deterministic agents, additive per-token costs, available caches and free switching.
