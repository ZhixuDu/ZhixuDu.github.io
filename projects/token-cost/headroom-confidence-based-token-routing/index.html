Headroom in Confidence-Based Small/Large Token Routing

How much headroom is left in confidence-based small/large token routing?

Answer

On MATH-500 there is measurable headroom. Du et al. (2026) gave a routing controller oracle access to the positions where Qwen2.5-0.5B matches a greedy Qwen2.5-72B reference. With that information, routing reached 69.60% accuracy at a projected 5.12 seconds per response. The best confidence-threshold cascade (threshold 0.99) reached 68.40% at 7.59 seconds, and 72B alone reached 69.20% at 19.03 seconds. Because the map requires advance access to the reference, this is an upper-envelope estimate of what better allocation information could unlock, not a deployable router.

The confidence baseline follows the TokenCascade Chow rule: use the 0.5B model when its maximum next-token probability is at least a threshold, otherwise ask the 72B model. Across thresholds of 0.5, 0.8, 0.95 and 0.99, it reached 40.00%, 60.00%, 66.60% and 68.40% accuracy at 2.80, 4.45, 5.91 and 7.59 seconds. The map-guided policy selects 0.5B at mapped positions, checks that the small model's actual token equals the stored reference token, and otherwise defers to 72B; once the generated prefix departs from the reference it uses 72B. All routing policies share a scheduler that collects deferred target requests after at most 16 small-model steps.

Paired against the 0.99 threshold on the same 500 problems, the map policy differs by +1.20 points of accuracy and -2.46 seconds of projected time. Map fallback occurred on 100 routing responses, and all departures stay in the totals. Logical compute was 96.71 TFLOPs versus 100.38 for the 0.99 cascade.

Projected times come from a model fitted to published vLLM benchmarks and exclude map acquisition. The paper names building controllers that recover this headroom without exhaustive model evaluation or advance reference access as an open problem.

Setup

All 500 MATH-500 problems with Qwen2.5-0.5B-Instruct as the small model and Qwen2.5-72B-Instruct as the target, greedy decoding, a common 1,024-token output cap, and symbolic-equivalence checking (Math-Verify). The map is supplied as an oracle from a fresh greedy 72B response; its acquisition is excluded from resource counts. Baselines: TokenCascade-style confidence routing at four thresholds, fixed 16-token drafting and confidence-adaptive drafting. Runs use a PyTorch 2.9.1 backend in bfloat16 with the target on four A100 80GB GPUs; latency is projected from official Qwen2.5 vLLM A100 benchmarks; 2,000 bootstrap resamples of problems.

Oracle map from a 72B greedy reference on all 500 MATH-500 problems; latencies are projections, not measured deployment times.
