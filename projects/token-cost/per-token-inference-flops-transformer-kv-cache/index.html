Counting Per-Token Inference FLOPs for Transformers with KV Cache

How do you count per-token inference FLOPs for a transformer with a KV cache?

Answer

Count matrix-multiplication FLOPs from the released model configuration, with one multiply-add counted as two operations, and add an attention term that grows with the cached prefix. Du et al. (2026) write the cost of one next-token prediction with p cached prefix tokens as c(s) = A + B p + H (Eq. 13). With hidden width h, query width q, key/value width r, L layers and vocabulary V, A sums 4h(q + r) for the query, key, value and output projections, 6h times the active feed-forward width for the gate, up and down matrices, and 2h times the number of routed experts for MoE routers. B = 4Lq covers the two attention matrix products per query-key pair, and H = 2hV is the vocabulary projection.

For sparse layers only the selected experts count; Qwen3-30B-A3B uses eight active experts out of 128 per layer. Embedding lookup, normalisation, activations, bias additions, rotary embeddings, softmax and expert dispatch are excluded, as are kernel padding, communication and memory movement. A whole request with m input and n generated tokens (Eq. 14) costs m A plus B m(m+1)/2 attention pairs for prefill, one vocabulary projection, and n-1 cached decoding steps at prefix lengths m+1 through m+n-1.

The paper's ledger shows why speculative decoding can lower latency while raising total FLOPs. On MATH-500, 72B alone used 101.92 TFLOPs at a projected 19.03 seconds, while fixed 16-token drafting used 154.30 TFLOPs at 4.98 seconds, adaptive drafting 140.52 at 4.69, and map-guided drafting 112.07 at 3.99. The ledger includes prompt prefill, cache catch-up, rejected drafts and target verification. Verifying n positions in one target call costs far less time than n sequential calls, so extra arithmetic can still shorten wall-clock time; logical FLOPs do not capture memory traffic.

Setup

FLOP accounting from released model configurations for dense Qwen2.5, OLMo-2, R1-Distill-Qwen and Falcon3 models and the Qwen3-30B-A3B MoE generator (Appendix B.1). The ledger is applied to actual forwarded positions and requested logits in the MATH-500 allocation experiments (all 500 problems, Qwen2.5-0.5B-Instruct draft and Qwen2.5-72B-Instruct target, greedy decoding, 1,024-token cap).

Counts are logical matrix-multiplication FLOPs; they exclude memory movement, communication and kernel effects.
